# RFC 0005：Arc、读写借用与解引用

## 状态与范围

- 已确认：`Arc[T]` 使用 Go GC 共享对象；`mut& T` 表达受检查的写引用；不引入全局 move 系统。
- 已确认的访问方向：`&T` 为只读路径，`mut& T` 为可写路径；普通引用允许复制、保存和返回，不承诺独占。
- 暂定：Arc / 引用的非空与构造协议、接收权限及完整投影类型表示。下列未冻结语法仍是候选。
- 未定：完整投影类型检查、返回签名覆盖、接收权限、明确不可复制类型及 Box。Box 的名称不构成唯一所有权规范。
- 本文规定源级权限与 Go 存储的对应关系，不把成功生成 `*T` 当成已完成借用检查。

D19/D20 边界：读写权限和已确认类型不变量照常检查；别名、留存、独占与重入风险分析独立长期推进，不属 MVP。未来仅有具体风险证据才 warning；未知不默认拒绝或告警。

设计背景：[引用专题](../design/pointers-and-borrows.md)。匹配中的借用见 [RFC 0009](0009-match.md)。

## 源级规则

| 源级形式 | 候选含义 | Go 表示 |
| --- | --- | --- |
| `T` | 值；读取允许复制时遵循该类型的复制规则 | `T` |
| `&T` | 经所选路径只读，不增加写权限，也不冻结其他别名 | `*T` |
| `mut& T` | 可复制的写访问，不承诺独占 | `*T` |
| `Arc[T]` | 可复制的共享句柄，复制保持对象身份 | `*T` |
| `Option[Arc[T]]` | 表达可缺失的共享句柄 | 由 enum ABI 决定 |

`*r` 首先表示一个存储位置：值上下文读取它，赋值上下文写入它。
自动解引用即使被支持，也不得先复制整个对象，或使读借用获得写权限。
建立引用和投影时要保存读写资格；相同的 Go 指针类型不能消除这些源级区别。
传参不自动暂停原写权限，也不要求先证明被调方未留存。若未来 API 声明临时访问契约，其违规风险按 D19/D20 另行研究，不恢复默认逃逸拒绝。
Arc 的共享性不自动授予独占访问；锁、原子或其他受审核协议另行提供访问途径。

## 转译示例

以下都是函数或函数体片段；`i32` 降低为 `int32`，`Item` 为已定义的普通对象类型。

**B01：解引用的读取与写入。** 两个函数分别检查权限；不增加运行时权限对象。

```hgo
func read(r &i32) i32 {
    return *r
}
func update(r mut& i32) {
    *r = 42
}
```

```go
func read(r *int32) int32 {
    return *r
}
func update(r *int32) {
    *r = 42
}
```

**B02：局部写引用与直接传参。** `update` 的写访问资格已知；接受调用不依赖不留存证明。

```hgo
var value i32
r := mut& value
update(r)
*r += 1
```

```go
var value int32
r := &value
update(r)
*r += 1
```

约束：`r` 始终指向 `value`。不得复制 `value` 后把副本的地址传给 `update`。
取址是否使 `value` 逃逸到堆上由 Go 编译器决定，不承诺零堆分配。

**B03：复制共享句柄。** 片段的输入 `a` 分别具有 `Arc[Item]` / `*Item` 类型。

```hgo
b := a
```

```go
b := a
```

约束：`a`、`b` 指向同一对象；无深复制，无额外原子引用计数。
复制不会凭空新增 Arc 的写访问 API；可取得的访问须符合其已声明协议。预先存在的可写别名不会仅因可能冲突而被拒绝，Arc 的具体访问方法仍待定义。

**B04：读借用写入应被拒绝。** Go 可以表达该操作，因此错误必须由 hgo 检查。

```hgo
func wrong(r &i32) {
    *r = 42 // 拒绝：经读借用写入
}
```

```go
// 禁止生成：这段 Go 可编译，但违反源级读权限。
func wrong(r *int32) { *r = 42 }
```

## 拒绝与边界

- `a := r; b := r` 可以复制同一 `mut& T`，保持对象身份与写资格；这不提供独占或无竞争保证。
- 不能偷偷复制 map 元素或临时值，再把副本的地址当成原位置的借用。
- 引用装入 enum、trait wrapper、容器或闭包后仍须保留读写资格；尚不能表达资格的类型边界可以明确报未支持，不能以此泛化为逃逸禁令。
- 读借用的禁止写入包括通过字段、方法及其派生别名修改受保护存储；检查精度仍未定。
- 共享字段的浅复制可能保留 slice / map / Arc 别名；借用外层 struct 不自动证明整个对象图独占。
- 普通引用返回和跨 goroutine 捕获不因留存或并发本身而拒绝；具体未支持的签名或资格传递形式须准确诊断。并发写冲突风险与类型错误分开。

这些边界约束类型资格与真实存储身份；不要求全程序别名分析或不逃逸证明作为准入条件。

## 双向互操作

hgo 调 Go 时，涉及引用/原生指针的实际类型桥接按 [RFC 0006](0006-foreign-api.md) 处理；普通未知 Go 调用不因缺少声明而拒绝或自动 unsafe。
`declare` 可描述读写契约，但验签只能证明 ABI 兼容；声明作者承担其明确承诺的不留存、无冲突重入等行为前提；没有此类摘要不构成默认拒绝理由。
Go 调生成函数时只看到 `*T`，普通 Go 调用方不获得 hgo 的静态只读检查；hgo 本身也不承诺独占或期限证明。
公开边界的非空检查方案见 [RFC 0015](0015-public-api.md)，判空不能证明独占。
模块中的 `.d.hgo` 保存源级权限；hgo 消费这些信息，Go 工具链只编译 `.go`。
本方案不要求给第三方原生 Go 程序追加一套 hgo 静态检查。

## 验收与未定项

1. B01–B03 验证读取结果、原存储更新和共享身份；B04 在生成 Go 前拒绝。
2. 增加写引用复制、普通返回及捕获的正例；只读升级和权限擦除为负例。具体别名冲突的未来 warning 单独验收，不计入 MVP。
3. 检查 IR 到 Go 的每次值读取和取址：复制不能替代原位置借用，布局相同不能提升权限。
4. Arc / 引用非空、构造与更宽返回签名、投影粒度和明确不可复制类型尚未定稿；这些待定项不撤销普通引用可复制、保存和返回的方向。
5. Box 仍待设计；不生成没有已定义语义的 Box ABI。
6. `-race` 只补充实际运行路径的竞争证据，不能替代转译前权限诊断。

当前验收表是完整特性的设计要求；仓库已有有限引用与投影前端，范围见实现记录。Go 夹具不能代替未实现的源级检查或长期 warning 分析。
