# 设计文档的可复现检查

这些夹具迁移自设计阶段已经运行的独立 Go 实验，只检查文档中的 Go 降低与支持库机制。它们不是 goxide 编译器、linter、宏展开器或 LSP 的测试，也不是这些功能的实现。

从任意目录运行以下入口（路径按实际 checkout 调整）：

```sh
python3 scripts/check_design.py --docs-only
python3 scripts/check_design.py
```

示例命令以仓库根目录为当前目录。脚本自身根据文件位置定位仓库，不依赖当前目录；从其他目录调用时给出脚本的实际路径。

文档检查需要 Python 3.10 或更新版本。完整检查还需要本地 Go 1.27 或更新版本，以及可运行 Go race detector 的平台和 C 编译器。脚本使用 `GOTOOLCHAIN=local`，不会自动下载工具链；隔离外部 `go.work` 与 `GOFLAGS`，不修改仓库或依赖中的 Go 文件，不创建仓库根 `go.mod`。

完整检查会创建临时模块，从设计文档提取完整 Go fenced code，并复制此目录中的既有行为夹具。执行日志、生成源码、环境与成功汇总保留在输出的临时目录；失败时也保留已产生的工件。临时目录可在检查结束后自行删除。文档正文、夹具和脚本都在版本控制中，因此复现不依赖某台机器旧的临时目录。

| 范围 | 持久夹具与验证内容 |
| --- | --- |
| 锁 | 13 项测试；原有 4 项，6 项边界/快照夹具，另有局部指针返回、只读并发共享和返回指针再获同锁访问正例；运行 `-race`，不代表 goxide 静态诊断实现 |
| 枚举 | 6 项测试；合法值、nil / typed nil / 伪造 case、嵌套 Option、可空 Ptr、外部回调和共享字段重读；另有 2 个泛型身份编译负例 |
| safe std 支持机制 | 7 项测试；部分读取与错误、零进展、容量、非法计数、浅复制与回调策略 |
| trait wrapper | 2 项测试；两个接口共享原状态及空目标拒绝 |
| 宏降低示意 | 两个完整 Go 程序，分别核对 `85 1 41` 与 `untitled 1 9 true 7`；不执行 goxide 宏 |
| 裸指针 | 6 项测试：原有转换/wrapper，原子与 flag 指针、bytes/容器/接口、回调 nil 桥接、持有者槽位与内部对象区分；1 个具名指针接收者编译负例 |

主要完整 Go 示例直接从文档提取，避免复制一份后悄悄偏离正文。Ptr 和历史 marker 注入使用独立机制夹具；后者已被统一 wrapper 设计替代，仅保留机制记录。它们不声称验证每个文档片段。负例要求编译失败且包含相关诊断，不把缺工具链等任意失败算作通过。

`go.mod.fixture` 仅在临时目录中变成 `go.mod`。marker 夹具的本地 `replace` 使用相对路径，不依赖用户目录或共享模块缓存。历史 GOROOT overlay 实验未纳入本套跨机器检查；不能因这里的 marker 测试通过就宣称任意工具链的标准库 overlay 已验证。

Markdown 检查覆盖仓库 Markdown 文件的围栏闭合、行内本地链接和 ATX 标题锚点；不访问外部 URL，也不是完整 Markdown 规范检查器。新增例子的提取失败应修正文档或显式更新脚本清单，不能静默跳过。

基线验证：2026-09-30，Python 3.14.7、Go 1.27.1、darwin/arm64（CGO 开启），完整入口通过。共执行 13 条 Go 命令：8 条正向测试命令、3 个预期编译失败和 2 个程序输出检查；正向测试共 25 次 Test 执行，其中原始 Go 消费方刻意在增强视图前后各运行一次。锁测试含 `-race`，原始依赖文件摘要保持不变。该基线当时未覆盖其他平台，不能将此记录视为 goxide 端到端实现通过。

## trait 双路径研究（D21/U16）

独立入口见 [研究说明](research/trait_paths/README.md)，主设计检查不自动运行性能基准。该实验对照原生/值视图/指针视图/无额外布局视图/直接函数/类型化字典，复测 Go 可选协议、marker 提升和源码发布路径；保留五次短基准与编译器诊断。它不是 goxide 前端实现或真实业务性能结论。

专用问号候选新增 3 项 enum Go 机制测试，覆盖 typed-nil、传播/求值顺序/defer、闭包/Option 和部分成功，完整套件正向 Test 次数增至 41；未测试 goxide `?` 解析或静态诊断。

[逐特性 RFC](../docs/rfcs/README.md) 另检查编号/文件名、六个必需章节，以及 goxide 和 Go 示例块是否存在。此结构检查不编译 RFC 片段、不证明转译对应关系；现有完整 Go 检查的提取清单没有自动扩展为所有 RFC。RFC 中的源级正反例在前端实现后才能成为端到端通过记录。
