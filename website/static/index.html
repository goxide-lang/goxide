    CLI 工程能力 · 浏览器外运行
    从单文件，走向真实工程。
    依赖与 feature 一起规划hgo.json 描述显式依赖、feature、可选 library、多个 bin / example target。version / git / path 标识源码；版本依赖沿用 Go MVS、proxy 与校验机制，hgo feature 在实际选中源码上合并。锁文件与缓存支持复现；offline 需要预热缓存，不冻结本地 path 内容。
    构建脚本需要明确授权CLI 的 host 构建脚本是本机程序，需要项目信任与依赖、helper、tool 的精确许可。所选版本、feature 与脚本身份参与缓存和 target 隔离。脚本没有沙箱；offline 不限制脚本网络。这些能力不在浏览器执行。
    统一 hgo API 入口use / pub use 可聚合类型、常量、函数、变量及当前源图宏。变量仍是原存储，宏保持定义点。普通 Go 的函数与变量应从原实现包访问；独立模块预编译产物尚不能发布宏。
    工程支持有范围仅显式激活的 manifest 依赖参与 hgo 构建，不自动扫描全部 go.mod 节点。纯 Go 包不能接收 hgo feature；源码与生成元数据不能混为双轨发行。增强构建按模块 DAG 工作，不承诺任意跨模块包交错。

    边界也是语言说明的一部分
    这不是完整 Rust，也不是全部 MVP。
    语法是有限子集完整 trait、用户过程宏、.hgo 用户泛型定义与 LSP 尚未交付。部分 match / ? 表达式组合仍会拒绝。跨模块 Result 的特定循环已消除逐项分配；最终结果仍可分配，不承诺零分配。设计中的能力不等于已经实现支持。
    协议有资格要求派生不隐式授予所有类型协议。递归 Default、循环容器 equality、手写 Clone / Debug / serde 登记仍有缺口。
    没有完整借用保证路径只读不等于全局不可变，写引用不承诺独占。这里不宣称完整 Rust 借用安全；复杂别名分析是独立工作。
    浏览器范围小于 CLI这里只转译单文件与随附包。跨模块恢复、构建视图、测试文件与交叉平台有各自边界，不在此 Playground 的支持范围内。
    本页描述当前已验证的语言子集；构建清单固定实际编译器版本、包支持范围和示例输出。
