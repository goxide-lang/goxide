# RFC 0003：先拆 Go 指针职责，再选择 MVP 类型

状态：2026-10-01，候选，未批准。D19 warning-first、D20 风险分析不属 MVP 不变。本轮不催定 RFC 0002 的桥接 A，也不因讨论名字就加入 Box/Cell。D08 已确认 Arc 方向；本轮补充其独立的 API 保留/转交意图价值，纠正仅按运行时能力重叠判断冗余。具体能力契约仍待选择。

## 1. 功能分解

Go 指针、容器和方法集的基础事实据 [Go 规范](https://go.dev/ref/spec#Representation_of_values)。以下 goxide 列是候选设计，不是 Go 自带只读/所有权保证。

| Go *T 常见职责 | 正向场景 | 最小 goxide 能力 | Go lowering / 是否需要智能指针 |
| --- | --- | --- | --- |
| 间接读取/修改原值 | 函数更新请求统计 | `&T` 读、`mut& T` 写 | 都以 *T 承载；不需独占持有类型 |
| 避免大值复制 | 读取大数组/配置 | 传 `&Large`，不要先复制整个 Large | 传 *Large；不要求 Box |
| 长期存活与共享身份 | 多个组件保存同一对象 | 可保存/返回的普通 GC 引用即可 | 共享同一 *T；不必引用计数 |
| nil / 缺失 | 可选父节点、查找未命中 | 高层 Option[引用]；原生可空指针视图 | 保留各自表示，Option 不默认等于 *T |
| 递归结构与图 | 链表节点指向下一节点 | 含 Option[引用] 的节点 | 指针间接打断递归值布局；不必独占 Box |
| 方法接收者/接口实现 | 原生 Buffer 作为 Reader | 保留真实 T/*T 身份与方法集 | 原生接口装箱；具名 Ptr 的方法不能凭空继承 |
| 输出槽位 | 原生函数替换一个 *T 结果 | 区分对象引用与保存引用的槽位 | *T 与 **T 区分；Option 槽位需真实桥接，不强转 |
| 原生互操作 | 指针入参/返回、回调 | Ptr/原生视图 + 合法类型桥接 | RFC 0002 候选；缺摘要不强制 unsafe |
| 同步访问 | 共享计数器与缓存更新 | Lock/RWLock 或原子 API | 普通 Go 同步；“是指针”本身不提供同步 |

slice/map/channel 已有共享存储或通信语义，默认不为它们再包 Arc。slice 头复制与底层数组共享不同，改变 len/cap 或替换 map/channel 绑定不等于修改其内容；需要改调用方绑定时才考虑槽位引用。字符串共享不可变字节；不能把这个事实推广到所有容器。[Go 类型与值表示](https://go.dev/ref/spec#Types)

取地址不承诺物理堆位置。Go 编译器按实际逃逸和优化决定分配；返回局部变量地址是合法用法。goxide 构造若声明间接存储，不应顺带承诺强制堆分配或“零分配”。[Go FAQ](https://go.dev/doc/faq#stack_or_heap)

## 2. 普通引用已经能承担多少持有职责

前轮已按 D19 允许引用返回、复制与长期保存，不再有“普通引用只能在词法块内存活、Arc 才能持有”的硬区别。这仅说明运行时可复用，不等于 API 上无需区分保留意图。以下是无名义持有层的对照方案，不再直接据此推荐移除 Arc：

- `T`、`&T`、`mut& T`：普通值与显式访问权限；写引用不承诺独占。
- 明确的间接构造，例如候选 `ref_new(value) -> mut& T`，或正常函数返回局部值的引用。名称未定，不同时引入多套构造名。
- Option[引用] 处理高层缺失，原生可空指针保留真实语义；Ptr/AsPtr 既有 D11 的协调仍另行处理。
- 已有 Lock/RWLock 访问协议及按实际类型调用的原子操作。不新增全套 Cell 系列才能使用并发。

这不是将“Ref”恢复为旧共享句柄类：`&T`/`mut& T` 是访问类型，旧 Ref 名字此前被 Arc 方向替代。Go GC 会保持可达对象存活，不论引用存入变量、闭包还是容器；此处不新增 GC 或引用计数。

### 基础只读规则不能只检查顶层赋值

`&T` 表示经这条访问路径不能写普通数据，不是“对象永远不变”。无需全程序别名分析，但必须在类型检查中保留投影权限：

```goxide
struct State { count int; items []int; counts map[string]int }
func inspect(r &State) int {
    n := r.items[0]           // 允许读标量副本
    r.count = n              // 类型错误：直接写
    r.items[0] = n           // 类型错误：投影仍只读
    r.counts["x"] = n        // 类型错误：map 内容写入仍沿该只读路径
    return n
}
```

复制字段 slice/map 头到局部变量不能自动清除这条路径的只读资格；需要明确的只读容器视图/类型限定保存权限，或实际复制元素取得独立容器。对仍携带受限访问能力的值，方法、接口/any 装箱、返回值和原生调用也不得静默擦除资格。独立的值副本不永久只读：`v := *r` 若 T 只含整数或固定值数组，v 可正常修改；含引用字段则仅相应投影继续受限。只读方法可以明确创建并返回新的可写对象，不对其所有结果机械传播只读；依靠类型化构造/声明及方法体的局部类型规则，不要求 MVP 证明未知堆别名。如何表示这种类型限定属于普通类型设计尚需完成的工作，不能说只有 `&`/`mut&` 两个 token 就完成了 MVP；其实现比全局别名分析小，但也非免费。

其他已有可写别名可以修改同一对象，不因此禁止 `&T`，也不承诺并发安全。显式内部可变能力另论：比如 Lock 的访问方法可以通过共享句柄调用；不能把这类协议包装成“深不可变”。未知原生写能力位置不接受隐式只读升级；已审核只读声明可以接受，详见 RFC 0002。只读类型错误仍 error，不降为未来 warning。

## 3. 场景与 lowering

### 3.1 大值更新、返回和保存

```goxide
struct Stats { samples [1024]int; total int }
func make_stats() mut& Stats {
    value := Stats{}
    return mut& value
}
func increment(p mut& Stats) { p.total += 1 }
func total(p &Stats) int { return p.total }

s := make_stats()
increment(s)
n := total(&(*s)) // 显式降为读访问，不复制 Stats
```

Go 分别是 `func makeStats() *Stats { return &Stats{} }`、`func increment(p *Stats)`、`func total(p *Stats)`。没有强制移动、独占或销毁规则；只读差异在生成前的类型层检查，Go 本身不表达它。返回的对象可长期保存，不需 Box 才避免悬空。

### 3.2 递归结构与可选边

```goxide
struct Node { value int; next Option[mut& Node] }
func prepend(value int, next Option[mut& Node]) mut& Node {
    node := Node{value: value, next: next}
    return mut& node
}
tail := prepend(2, Option::None)
head := prepend(1, Option::Some(tail))
```

该语法仍是候选；不存在“必须先有 Box 才能写递归结构”的要求。Go lowering 中 Node.next 使用现有 Option interface/case 承载 `*Node`，不是未经确认的 nil 指针优化。复制边会共享目标节点；若业务需要不可变图，采用只读边及对应路径权限，不能凭节点名保证。

这里展示当前允许保存引用的 Go 兼容模型。prepend 把 next 内的引用保留到返回节点；若选择第 7 节 H 的临时访问契约，需要另行表达保留/返回关系或采用持有字段。该契约是否覆盖 Option 内嵌引用也尚未定义，不能把两套候选混成已经批准的规则。

### 3.3 缓存共享更新

```goxide
cache := Lock.new(Stats{})
cache.do(|p| { increment(p) })
answer := cache.do(|p| { return total(&(*p)) })
```

已有 .do 在持锁期间给 `mut& Stats`，Go lowering 调用现有 Do(func(*Stats)...)。RWLock.read/write 分别提供读/写访问。Lock 已是可复制指针句柄，无需额外 Arc[Lock[T]]。Lock[引用] 只锁住对应存储和协议，不自动保护其他别名访问整个对象图。回调引用可能逃逸；没有 MVP 分析器阻止它，不能把回调签名当作静态无竞争保证。

## 4. 如果保留持有类型：接口候选与槽位区别

以下是两套小方案，均未批准：

| 方案 | 用户能力 | 收益与代价 |
| --- | --- | --- |
| R：普通引用 + 保留契约（对照方案） | 可保存的读/写 GC 引用 + 一个构造入口；锁/原子管理内部变化 | 类型数量少，直接满足递归/大值/共享；与 D08 Arc 已确认方向需显式协调，不能直接删掉 Arc |
| H：显式 Arc 保留标记（优先评估） | Arc 表达允许保留/共享/转交；临时读写引用表达访问；Box 仍独立延期 | 持有意图更显式，但若 Box 可复制且直接给写引用，与普通写引用重叠；Arc 只读投影也不是独占/不可变保证 |

H 的最小方法建议是 Box（若加入）提供 `as_ref -> &T`、`as_mut -> mut& T`；Arc 只提出 `as_ref -> &T`，**不提出任意 Arc.as_mut**，内部修改通过显式 Cell/Lock/原子能力。所有新方法都是候选，不声称仓库原已有这些 API。只有在类型确有对应方法时才能取得内部引用；A 桥接不负责取得引用。

| 已有/候选持有者 | 读链路 | 写链路 | 槽位与内部的区别 |
| --- | --- | --- | --- |
| `value: T` | `&value` | `mut& value` | value 本身是 T |
| `r: &T` / `w: mut& T` | r / `&(*w)` | 只有 w 可直接传递 | `mut& w` 针对保存引用的槽位，不是重新取得内部写权限 |
| Box[T]（H 候选） | `box.as_ref()` | `box.as_mut()` | `mut& box` 指向 Box 绑定；不隐式解包 |
| Arc[T]（H 候选） | `arc.as_ref()` | 普通 T 无 as_mut；内部可变对象调用其明确协议 | `mut& arc` 是句柄槽位引用，不是 mut& T |
| Lock[T] | `.do` 内显式降读 | `.do` 回调给 mut& T | 对锁句柄取址不等于对锁内 T 取址 |
| RWLock[T] | `.read` 回调给 &T | `.write` 回调给 mut& T | 同上 |

若 H 加入 Box，最简单可实现含义是“GC 间接存储，可复制句柄”，而非独占或确定析构。这个名称与 Rust Box 的所有权行为不同，必须明确说明；若未来改成独占会是语义变更，不能悄悄升级。Arc 同样沿 D08 使用 Go GC，不是 Rust 的原子引用计数，也不提供 strong_count/get_mut 唯一性 API。

Rust 官方 Box 的确首先用于拥有堆分配，并支持递归结构；同时具有离开作用域销毁其内容等所有权语义。goxide 应拆开“间接存储”“物理堆位置”“独占”“确定销毁”，不能因需要前一项就要求后三项。[Rust std::boxed](https://doc.rust-lang.org/std/boxed/index.html)

lowering 可把候选 Box/Arc 都用 *T 承载，内部引用投影为同一指针，句柄槽位为 **T；不要求实际两次分配。投影方法应由前端内建/支持函数降低，不能给任意外部 T 增加 Go 方法。若 T 恰有同名方法，候选规定显式持有者方法优先；要调 T 方法先取得内部引用，避免隐式递归解包。这项名称解析仍需与 U03 一起确认。

`&Box[T]` 若可复制出 Box 副本再 as_mut，就不可能宣称递归不可变；例如 `a: Arc[Box[T]]` 中复制出 `b := *a.as_ref()` 后再 `b.as_mut()`，会绕过读投影。H 的 Box 因此尚未闭合：建议读路径复制保留只读持有视图资格；若改为把 Box 本身当内部可变能力，必须独立明确批准，不能默默列为例外。仅让 as_mut 要求可写局部绑定不足以解决。这个额外类型限定是暂不加入 Box 的理由之一，不应引入全程序唯一性证明来掩盖。Arc 只给读投影也不能撤销创建前存在的原生可写别名。

## 5. 内部可变：先复用已有协议

Rust Cell 用值操作，RefCell 动态检查借用；它们不等于跨线程同步。Rust 同步模块提供锁及原子等机制。[std::cell](https://doc.rust-lang.org/std/cell/index.html)、[std::sync](https://doc.rust-lang.org/std/sync/index.html)。下列是 goxide 取舍，不是复制 Rust 的安全保证：

| 机制 | goxide 真实需求与候选 | MVP 建议 / 缺失代价 |
| --- | --- | --- |
| Cell 小值 get/set/replace | 通过只读外壳更新指定字段，不暴露 mut&；适合标量缓存 | 可延期；先用直接写引用/Lock。泛型返回引用型 T 仍可能共享，不能称深快照 |
| RefCell 动态借用 | 单线程重入检测；需要明确结束借用及逃逸规则 | 延后。Go 没有 Rust guard 自动析构语义；回调 defer 恢复计数后，逃逸裸引用仍能访问，计数器无法全面保护 |
| Lock/RWLock | 跨任务数据访问协议，已有设计与 Go 夹具 | 复用，不再增加一套同义 Mutex 类；不承诺全图独占或阻止原生绕开 |
| 原子操作 | 单个计数/状态的同步 | 复用具体 Go API；不自动使多字段业务更新成为事务 |

H 下示意链为 `arc.as_ref() → &Cell[int] → set(value)` 或 `arc.as_ref() → &同步对象 → 该对象访问方法`；方法明确授权内部变化，不是把 &T 隐式变成 mut& T。不要求现阶段同时提供所有这些类型。单线程 Cell/RefCell 的误用不能靠尚不存在的 Send/Sync 或借用分析宣称已被阻止。

## 6. 推荐、现有决策冲突与验收

前轮只比较运行时能力，因此偏向删除独立持有类型；这一判断不充分。现在优先评估 H：保留 D08 的 Arc 名义类型，显式表达允许保留/共享/转交的 API 意图；与 R 的参数保留契约对照见第 7 节。两者都使用 Go GC，无需原子引用计数。Box/RefCell/确定析构/全局借用分析仍不由此进入 MVP。

唯一关键选择改为：是否采用“Arc 名义类型表达保留/转交意图，引用表达临时访问契约”的方案 H？推荐作为下一步候选，不标为用户已确认。不保留的实现保证仍需可信契约或未来 warning，不能同时声称普通引用任意逃逸合法且已强制临时性。此选择不批准 U15 桥接 A，也不默认增加 Cell。

当前仅基础只读/可写类型规则属于语言实现；别名风险 warning 和静态借用分析按 D20 全部长期独立。Go 夹具验证大对象指针身份、返回存活、槽位重绑定不改变旧别名、带锁访问等机制，不能证明新的 goxide 类型投影、Cell 或未来分析器已实现。物理分配和性能没有基准证据。

独立审查已修正两点：只读投影不限制独立标量/值数组副本，也不机械限制新分配返回值；可复制 Box 经只读 Arc 恢复写能力的链路明确列为 H 未闭合问题，而非默认内部可变特权。

### 6.1 最小集合与现有决定的核对

**运行时最小能力与已确认的语言产品范围不同。** 普通 GC 引用足以承载递归/共享身份，是机制判断；取消 Arc 却会改变 D08，尚未授权。第 7 节的默认临时访问契约也不是 D08 已规定的寿命规则，不能把当前允许的引用保存突然变成 MVP 错误。

| MVP 建议 | 已有决定与未闭合部分 | 保证与缺失代价 |
| --- | --- | --- |
| 普通读写引用、取址/解引用、写权限收窄为读权限 | D08 一致；U02/U03 的投影与接收者权限待定 | 不承诺独占或对象全局不变 |
| 显式可空原生视图、Option、引用构造/返回 | D08/D12 一致；T02 的初始化/构造拼写待定 | 不承诺物理堆分配；Option 不等于原生指针 ABI |
| 保留 Arc 共享句柄方向，收敛构造与读访问接口 | D08 已确认；H 保留契约仍是候选 | 有名义类型成本，不提供引用计数、Send/Sync 或逃逸证明 |
| 复用 Lock/RWLock 与 Go 原子 API | D09；依实际协议同步 | 不阻止外部别名绕过锁；GC 不等于无竞争 |
| 延后 Box、Cell 家族、RefCell/确定析构 | 没有新增类型批准 | 少了专用装箱表达、指定字段内部可变门面及动态借用冲突检测；不是不能表达递归与共享 |

D11 是另一项真实约束：不能仅因后端同为 *T 就省掉已规定的 AsPtr/unsafe。便利桥接需 U15 的窄变更；缺效果摘要本身不要求 unsafe（D19）。本轮不催定桥接 A。

基础只读类型验收至少应包括以下反例：

```goxide
func inspect_again(r &State) {
    items := r.items
    items[0] = 1           // 类型错误：slice 头复制没有取得写权限
    counts := r.counts
    counts["x"] = 1        // 类型错误：map 值复制没有取得内容写权限
    n := r.count
    n += 1                 // 允许：独立标量副本
    copied := make([]int, len(r.items))
    for i, item := range r.items { copied[i] = item }
    if len(copied) > 0 { copied[0] = 1 } // 允许：实际新建的 int 存储
}
```

写接收者方法、接口/any 装箱后再断言、返回和回调同样不能擦掉资格。限定必须存在于类型/接口视图和断言规则中，仅给源变量附标签不够；MVP 支持范围待这些规则选定，不能依赖 D20 的跨函数来源分析补洞。channel 通信、锁、原子等显式能力应另依协议定义，不能机械冻结所有共享对象。这里列的是类型验收要求，不是当前可执行 goxide 测试。

本轮推荐是“引用能力优先、保留 D08 Arc 方向、复用锁、不新增 Box/Cell 家族”，不是批准一套完整智能指针库。GC 与同步的区别参见 [Go 内存模型](https://go.dev/ref/mem)。

### 6.2 权限验收补充：复制不等于解除访问限制

下列是 U02 的候选基础类型规则，不是对运行时别名的推断，也不是已实现测试：

| 路径或操作 | 推荐判断 | 原因与可用替代 |
| --- | --- | --- |
| 从只读路径取得 slice 后 `append(items, x)` | 类型错误 | 容量足够时会写原数组；不能依赖本次容量猜测权限。先新建并复制元素再 append |
| `copy(items, src)`、`clear(items)`；只读 map 的 `delete` / `clear` | 类型错误 | 内建操作同样需要目标内容写权限；只读 slice 可作为 copy 的来源 |
| 新建 slice 后复制其中的整数 | 允许写新 slice 的元素 | 新存储和标量副本独立，不能把一切派生值永久标成只读 |
| 新建 slice 后复制其中的对象引用 | 允许替换新 slice 的槽位；不能由此写原引用目标 | 只复制外层数组，不升级元素引用权限；需要写目标就显式取得合法写引用或复制目标数据 |
| 只读路径调用写接收者方法 | 类型错误 | Go 的指针方法集不表示 goxide 写权限；不能通过自动取址、trait 适配或函数值捕获提升 |
| 将受限容器装入接口再断言成可写容器 | 类型错误 | 接口视图/装箱必须保留资格，断言不是取得权限的操作 |

这里的“只读”约束所选访问路径；预先存在的另一个可写别名仍可修改对象。仅靠 Go `*T` / `[]T` / `map[K]V` 无法表达上述差别，必须由 goxide 类型层保存限定，Go lowering 才可复用原表示。Go 导出边界外的未检查代码不受此规则强制约束，不能宣称整个对象图已不可变。未知原生效果本身不拒绝调用；但确有受限实参时，原生参数视图仍须能接受其权限，不能把“未知不报风险 warning”误作允许权限擦除。只读声明、显式适配或复制可解决具体接口不匹配，不要求整个 Go 标准库预先有摘要。

**范围结论：**D08 阻止未经确认删除 Arc，不阻止先交付普通读写引用；D11 阻止未经确认省略转换边界，不阻止采用 GC 引用模型。真正尚待闭合的是 U02/U03 的类型限定、投影与方法权限，以及 U05 的递归 Go 类型视图。H 的默认临时访问契约仅作比较，不应成为实现这些能力或通过 MVP 验收的前提。

独立审查补充：`items := r.items` 也不能直接传给要求可写 `[]int` 的 `edit(items)`；限制必须参与实参匹配和泛型替换，不只是禁止赋值语句。只读视图的具体类型表示尚未选定。H 若不允许同身份的引用采用，已有 Go 对象注册可能被迫复制而改变共享身份；这是真实易用性代价，D08 没有规定必须如此。默认不保留及采用限制须独立审议，不能靠 Arc 名称推导。

### 6.3 本轮功能审查的交付边界

推荐先交付访问能力，而不是按 Box/Ref/MutRef/Arc 名单逐个造类型：读写引用、合法取址与解引用、权限收窄、显式缺失表示及构造/返回。这里的“先”是候选实现顺序，不撤销 D08 的 Arc 产品方向，也不把第 7 节的保留契约当成准入条件。Box 的装箱表达、Arc 的名义共享表达都须说明比普通 GC 引用多出的用户收益；运行时表示相同不是删除已确认类型的授权。

验收分三层：语法/类型检查验证实际支持的权限路径；Go 机制夹具验证返回存活、共享身份、槽位及同步行为；长期风险分析验证有证据的 warning。三者不得互相代替。尚不支持的复合权限形式应如实列出实现范围，不能仅凭顶层只读测试通过就宣称完整只读模型已实现。基础类型规则不依赖全程序别名分析，但仍需要符号身份、类型化投影及跨调用的权限签名。

官方依据的适用边界：Go 的[值表示](https://go.dev/ref/spec#Representation_of_values)说明哪些值共享底层存储，[结构体规则](https://go.dev/ref/spec#Struct_types)说明递归布局限制，[栈堆说明](https://go.dev/doc/faq#stack_or_heap)说明分配位置不是取址语法承诺，[内存模型](https://go.dev/ref/mem)规定同步关系。这些材料不提供 goxide 只读权限或 Arc 保留契约的证明；那些仍是本 RFC 的语言设计候选。

## 7. Arc 的 API 能力标记：保留与访问，不是同步与异步

本节所有方法/属性拼写为候选。H 建议 `&T`/`mut& T` 参数默认表达“本次调用访问，不保留到调用之后”的契约，`Arc[T]` 表达允许保留同一对象与转交。**MVP 不证明前者的实现守约**：契约违规不会仅因未证明不逃逸而阻断；未来有具体证据可 warning。Go GC 对已经泄漏的引用仍保持可达存活，不能把协议违规说成必然悬空。若语言允许显式返回引用，返回关系要在 API 中说明，它不是暗中保证所有引用都严格临时。

### 7.1 同一业务的两个签名方案

```goxide
struct Config { limit int }

// H：候选名义能力区分。
func read_limit(c &Config) int { return c.limit }
struct Registry { saved Option[Arc[Config]] }
func register(r mut& Registry, c Arc[Config]) {
    r.saved = Option::Some(c) // 同步调用，却明确保留
}
func start(c Arc[Config]) {
    go func() { report(read_limit(c.as_ref())) }()
}
func start_value(limit int) {
    go func() { report(limit) }() // 后台任务只传值，不需要 Arc
}

// 调用者：Arc.new/as_ref 均为候选名称，不是已批准基础包。
shared := Arc.new(Config{limit: 10})
n := read_limit(shared.as_ref())
var registry Registry
register(mut& registry, shared)
start(shared)
start_value(n)
```

`report(int)` 在例中为普通消费值的业务函数，无共享对象前提。H 的 Arc 复制共享同一对象，只提供读投影；内部修改走 Lock/Cell/原子等明确能力，不从 `Arc[T]` 推出 `mut& T`、线程安全或不可变。Lock 本来就是可保存的共享同步句柄，不要求为了标记保留再无意义套 Arc；协议可在签名中直接使用 Lock[T]。

R 保留同一个普通引用类型，改由参数契约表达区别，以下属性仅是对照记法，不拟引入一整套 effect 系统：

```goxide
func read_limit(c &Config) int // 参数契约：调用结束不保留
func register(r mut& RegistryR, c &Config) // 参数契约：may_retain(c)
func start(c &Config) // 参数契约：may_retain(c)，交给后台
```

R 的调用都可传同一个引用，迁移 Go 最轻；但普通类型不显示保留区别，文档/元数据易遗漏，函数值擦除时必须保留契约说明才有可读性。H 通过函数值参数类型继续保留 Arc 标记，工具可以只做正常类型匹配；两者仍都不能仅靠签名证明函数体未保存引用。

### 7.2 作用域任务与原生边界

```goxide
func report_before_return(c &Config) {
    done := make(chan int, 1)
    go func() { done <- c.limit }()
    report(<-done)
}
```

这个任务在发送读取结果后不再访问 c，调用方收到结果才返回，因此可以满足“返回后不再访问，也不向可继续使用的外部位置保留引用”的契约；不要求任何异步代码都接收 Arc。收到结果不证明 goroutine 已退出或捕获引用已经从 GC 根消失；契约不定义成返回瞬间物理上无引用残留。上述事实依赖具体实现，MVP 不做一般 join/cancel/逃逸证明；取消请求也不等于任务完成。goxide 的 &Config 只读并不阻止外部别名同时写。

Go API 可能同步保存指针（注册回调、缓存），也可能异步复制值。原生签名 *T 不表明 retain，也不能机械导入成“已证明临时”引用参数。无声明时标为保留行为未知，正常调用，不默认 warning/unsafe；明确声明可记录保留关系，或在 goxide 包装 API 选择 Arc 参数表达意图。Go 导出的 Arc 即使降低成 *T，未检查 Go 调用方也没有名义保留/只读保证。真实类型/桥接错误仍检查，不能因契约未知忽略 ABI。

### 7.3 转换会不会洗掉保留意图

H 建议 MVP 不提供隐式 `&T → Arc[T]`，也不默认提供无条件 `Arc.from_ref(r)`。直接把 &T 实参传到 Arc 参数是名义类型不匹配，而非全局借用分析。可用 `Arc.new(value)` 明确创建持有对象；按现有 Go 值语义复制 T，不是假定 move。`Arc.new(*r)` 对纯值数据形成独立对象；含 slice/map/引用字段时只是浅复制，不能清除内部别名或继承的只读资格，类型系统必须保留它们。需要独立数据就选择真实逐字段复制；不隐式深复制。

若以后需要“保持同一对象身份的引用→Arc 采用”，须单独显式命名并定义契约，不能把它描述成静态证明。这种普通 O(1) 采用会让任何借用轻易变成持有，降低名义门槛的约束力；最多保留调用者主动承担保留的意图。若想让转换证明所有权/无外部引用，就重新进入长期分析或运行时协议，不在 MVP 增加这个承诺。

Arc.as_ref 也可能被恶意/错误实现长期保存，名义标记只改善 API 边界，不能阻止所有“先降为引用再保存”的路径；不隐藏这一缺口。已有来源是否来自 Arc 无需 MVP 跨函数追踪，不能用“只准恢复来自 Arc 的引用”暗中引入分析器。

### 7.4 MVP 能检查什么与成本

| 项目 | H | R |
| --- | --- | --- |
| 基础类型检查 | Arc 与引用名义区分、参数/返回/函数值匹配、显式构造与只读投影 | 普通读写引用匹配，保留契约可只记文档/元数据 |
| 不保留实现 | 契约/未来具体风险 warning；Arc 标记不是逃逸证明 | 同样，参数注解不自动验证函数体 |
| Go lowering | Arc 与引用均可为 *T；构造按值建对象，复制句柄不加引用计数 | 普通 *T；若只加契约没有额外对象 |
| 成本 | 增加名义类型/构造/投影规则；构造可能复制/分配，非自动零成本 | 类型少，但文档、回调契约和API审查负担更大 |
| 可维护性 | 保留意图在签名可见，符合 D08 原方向 | API 变化可能只改契约而不改类型，易漏审 |

本节不是恢复MVP静态借用检查；Arc 不是线程许可，且不能凭复制行为增加写权限。基础只读路径规则仍需处理容器和接口资格，Box 相关漏洞不因 Arc 名义化消失。

### 7.5 对 Rust 迁移的帮助与限度

Rust Arc 使用原子引用计数共享所有权，通常需内部可变机制来改共享数据；它本身不令 T 线程安全，Send/Sync 有相应类型条件。[Rust Arc 官方说明](https://doc.rust-lang.org/std/sync/struct.Arc.html)。Rust 的 Send 表达跨线程转移，Sync 表达共享引用可在线程间使用。[Rust Book](https://doc.rust-lang.org/book/ch16-04-extensible-concurrency-sync-and-send.html)

goxide 的标记可提前暴露“临时访问 vs 保留共享”及同步位置，便于人工重构成 Rust API。但 goxide 使用 GC、可复制写引用、允许未检查引用逃逸、没有已实现的生命周期/Send/Sync 和确定析构，循环与释放行为也不同；不能机械改名直接转 Rust。作用域任务需映射到相应生命周期机制，共享可变数据需重审内部可变与线程条件。降低未来迁移的理解成本，是独立于运行时实现的真实收益，不是兼容性保证。
