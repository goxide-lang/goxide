# RFC 0001：Go 兼容的别名风险诊断

更新：2026-10-01。**用户已否决前两轮“无法证明安全就默认拒绝”的策略。** 默认允许 Go 风格指针传递、别名、返回与共享；仅对有具体风险依据的操作给 warning。本文替换前两轮 B01–B08 的默认行为，不将旧严格方案留作隐含前提。严格模式仅为未批准备选，不能默认开启，也不能自动把 warning 当 error。

风险静态分析按用户最新 D20 是独立长期工作线，完全移出 MVP；W01–W06 也不要求 MVP 实现。不为其预设强制 effect 注解或保守限制。

已确认的是上述诊断方向（D19）；以下诊断编号、精度、语法与实现路线仍是候选，尚无 goxide 检查器。D01–D18 中与本次无冲突的约束保留。尤其 D11 的显式 unsafe/AsPtr 不因降低警告级别自动取消；T01 的“所有未知 Go callable 都 unsafe”和 T06 的默认阻断已被否决，详见[决策登记](../../design/decisions.md)。[业务场景](0001-usage-and-tradeoffs.md)给出允许、警告和无依据不报的完整写法。

## 1. Error、warning 与不报告

| 分类 | 依据 | 行为 |
| --- | --- | --- |
| error | 语法无效、名称未解析、真实类型/ABI 不匹配、缺少或重复 impl、方法选择歧义、不完整 match 等可判定语言错误 | 阻断；不因 Go 兼容目标制造隐式转换或忽略错误 |
| error 的显式边界 | 已选定只读类型上的直接赋值、调用明确要求写接收者的方法；明确标为 unsafe 的操作缺少 unsafe 上下文 | 保留该类型/效果约束；接收权限的最终类型语法仍未冻结，不扩大为全局独占证明 |
| warning | 有可展示的来源、操作及可能冲突/协议离开路径，见 W01–W06 | 默认继续生成普通 Go；附原因、建议和分析限制，不额外插入复制/锁/panic |
| 无依据不报 | 仅知道某函数无摘要、仅存在指针/Arc/闭包/别名，或分析预算不足而无风险链 | 正常编译；这表示未发现具体风险，不表示已经证明安全。覆盖率/未知边界可在报告中按需展示，不逐调用刷警告 |
| 运行时边界验证 | 已选定的 enum/非空值不变量检查发现非法输入 | 保留原有检查行为；不把已执行的非法值检查改成继续使用坏值，也不将暂定 ABI 升级为已确认 |

`&T` 的源级只读含义与“其他别名绝不会写”分开；后者不是默认保证。Go 普通 GC 指针返回局部变量不会仅因源词法块结束成为悬空指针。业务资源 Close、锁协议和 cgo/unsafe 地址有效性是不同问题。warning 模式不提供静态内存安全、无数据竞争、无死锁或资源存活证明。

## 2. B01–B08 的新默认解释

### B01：来源用于解释风险，不用作默认准入证明

保留局部赋值、字段、闭包和锁句柄别名的来源线索。允许复制指针和顺序传参，不因活跃词法借用要求额外内块，不因证明不了唯一性拒绝 `mut&` 的正常使用。源级可写/只读类型仍检查；既有 `mut&` 独占检查方向调整为风险诊断，具体关系见 D08 与 D19。

分支合流只用于寻找可行风险路径：不得将互斥分支的两个访问拼成实际同时发生的冲突。来源未知不是 error/warning 的充分条件。暂不支持的语法仍是语法/功能诊断，不伪装成借用安全失败。

### B02：返回、装箱与复制默认允许

trait wrapper、方法值、error、panic payload、Option/Result 和容器都可能保留原引用；检查器保留这些线索，但不统一禁止其存储/返回。普通对象返回没有具体风险则不报；明确来源于锁保护数据，且后续访问或已声明不留存协议提供具体违约证据时，可给 W01；仅返回不报。GC 可保持对象存活，警告应说“保护已结束”，不能说“必定 use-after-free”。

已确认 trait 显式实现、完整候选方法集和类型身份检查不降级。独立值复制与深复制仍区别对待，但复制不是通过编译的强制条件。

### B03：异步交接检查实际冲突线索

goroutine 捕获、channel 传递、回调留存默认允许。只有可追踪的同一可变存储在不同任务中至少一方写、没有已知共同同步且可能并发时，给 W02；锁内指针后续使用违反已知协议还可有 W01，合并重复诊断。无冲突访问、独立数组值副本、已知 channel/锁排序，不报相关警告。复杂同步未识别可能误报；间接别名、反射、未知 Go 代码可能漏报。

error 与 panic 只是传播载体：允许携带普通对象，携带已知锁内引用先记录来源，仅有后续协议违约证据才 W01。defer 不统一禁止；仅对已知 Close/Unlock 顺序之后的实际使用给对应风险警告。

### B04：普通 Go API 无摘要也正常调用

真实 Go 签名/布局合法的普通调用、函数值传递无需因为缺摘要而写 unsafe，不强制作者先补 declare。摘要可增进告警精度，不是全生态准入门槛。只有已知方法/回调链回到当前锁、已知保存行为与具体后续风险等才报告；“fmt 可能调用任意方法”但没有具体接收者/路径时不逐次警告。

声明仍有价值：补类型视图、描述是否留存/同步/结果来源、帮助定位风险或消除误报。声明和 Go 方法集不证明行为；错误摘要可能漏报。Go 内部 mutex 不等于重入用户当前锁，也不要求所有库函数纯净。

### B05：锁构造和共享容器不要求唯一性证明

允许 `Lock.new(existingMap)`、slice 及含引用字段的值，不隐式复制。单纯浅复制不报；若观察到外部别名绕开锁继续访问同一存储且至少一方写，则 W03。已知顺序访问且无并发不报数据竞争，但若确有指定锁协议仍可报告协议绕开，并明确不是已发生 race。

已知同一非重入锁在持有期间再次获取给 W04，不阻断。Read→Read 只有识别到禁止递归的具体协议（例如 Go RWMutex 的递归读风险）才警告，并说明不一定每次死锁；未知锁不假定不支持重入。不同锁的全局顺序未分析不报“无死锁”，也不因身份未知而拒绝调用。

### B06：trait 身份错误与使用风险分开

D05–D07 的 declare 返回自身、有体 wrapper、期望类型适配不变。接收形式是否进入 impl 键仍为 U03 待选项，不能用前轮未确认方案强迫用户拆 trait。精确类型/方法候选不匹配仍 error；匹配之后，别名/逃逸只是按证据给 warning。

若未来选择按权限区分 impl，同一 trait 的 declare 擦除为同一 Go 接收者时公共 marker 去重、适配入口按完整身份区分；marker 不证明权限或并发安全。方法值捕获原接收者照常允许，只有具体风险链触发告警。

### B07：unsafe 不是未知效果的兜底标记

保留 D11 明确的 `unsafe <expr>`、显式 AsPtr 导出及明确声明为 unsafe 的 callable 属性；真实危险转换/操作的范围仍须逐项定义。不再把普通 Go 函数因“无摘要”自动标成 unsafe。原生视图、declare 和包装层依然存在，但不能命名成“未检查所以不可调用/整个声明包所以安全”。

旧 raw Ptr 默认映射与 D11 在普通 Go `*T` 参数处可能产生易用性冲突，**U15 待协调**：候选是保留显式 AsPtr 但提供普通原生参数的合法视图桥接，或修订原生指针导入策略。此轮不取消 D11、不发明隐式 Ptr→非空/只读转换；ABI 已相容的原生值可普通传递，明确 AsPtr 操作仍显式 unsafe。此限制必须以类型/明确操作为依据，不能重新包装成“缺摘要就 unsafe”。

已知导出后被保存并发生冲突访问可 W02/W03；仅向未知函数传递 Ptr 没有风险链不报，也不永久污染对象并禁止后续读取。分析报告可注明外部行为未检查，不将无警告称为安全恢复。

### B08：资源状态只做有依据的检查

不引入全局 move、线性关闭或默认 RAII。复制句柄允许，已知 Close→同句柄/别名 Read、重复释放或已使用 mutex 值复制给 W05/W06。Close 后某 API 本来返回错误时提示“可能业务失败”而非“内存不安全”；无法确定资源语义不猜测。推荐使用已存在的错误处理/defer，而非强制改为新资源系统。

## 3. Warning 清单与成本

每条 warning 输出主操作、来源链、已知协议/风险条件、建议和分析限制；同一来源的一串 wrapper/方法值合并到一个诊断。建议允许按诊断码局部抑制并写原因，具体配置语法未定。抑制不改变类型、不授予安全证明；默认不提升 warning 为 error。

| 编号 | 必要依据与可理解诊断 | 修复建议 | 误报/漏报成本 |
| --- | --- | --- | --- |
| W01 lock-view-escape | `lock.value → wrapper/error/方法值/panic → 已知锁外访问或明确不留存契约违约`：“该访问未遵循已知保护协议”；仅离开词法范围不报 | 若需独立结果可复制；或把操作留在锁内；若后续由同一协议同步可说明/抑制 | 仅同步串行使用可能无害，故 warning；未知包装器隐藏来源会漏报 |
| W02 possible-concurrent-alias | `same storage → 任务捕获读 + 父任务写`，缺少已识别 happens-before：“这两处可能并发访问同一数据，其中一处写” | 用同一锁/channel 排序，值快照，或避免并发写；建议跑 race | 自定义同步可能误报；分支/接口/外部代码可能漏报；不能声称实际 race |
| W03 lock-bypass-alias | `input backing store → Lock.new(input) → 原别名外部写`：“此写入绕过保护该存储的锁” | 通过锁更新或显式复制构造；串行协议可注明 | 共同外层锁/串行约定可能误报；跨包隐藏别名会漏报 |
| W04 lock-reentry | `持锁 L → 已知回调/方法 → 再获取 L`，且协议不支持该用法：“可能阻塞于自己持有的锁” | 合并到一次回调或调用不重新加锁的内部 helper | 路径不可达/自定义重入锁可能误报，需检查协议；间接动态回调可能漏报 |
| W05 resource-after-close | `alias → 已知 Close → 同对象使用`：“该操作发生在关闭后，可能返回错误” | 调整生命周期或明确处理预期错误 | 故意探测错误可能误报；重开/状态别名分析不足会漏报 |
| W06 copy-used-lock | `已使用的 Go mutex 值 → struct/数组赋值副本`：“复制锁状态不会复制其保护协议” | 复制句柄而非锁值 | 未识别使用状态可能漏报；自定义类型需明确协议，不因类型名猜测 |

W01 需要具体协议违约证据，不要求同时发现并发；仅有引用返回不报，已知同锁/相容原子协议访问不报，见 [RFC 0002](0002-native-pointer-bridge.md#4-w01-收窄先有协议再有使用风险)。W02 需要冲突访问线索。若同时成立，主诊断展示实际访问链，W01 作附注。普通 `return &local`、只读共享、无摘要 API 本身均不触发这些规则。

## 4. 实现方案与范围

以下全部风险分析方案都不属于 MVP；当前只推进语言语义和机制证据。复杂度拆分与自然可分析性信息见 [RFC 0002 第 6 节](0002-native-pointer-bridge.md#6-分析复杂度与-mvp-边界)。

| 方案 | 收益/难度 | 成本及边界 |
| --- | --- | --- |
| 局部来源诊断（长期候选，不属 MVP） | 已知锁重入、锁内值传播、Close 后使用、已使用锁复制；中等复杂度，需类型化 IR/CFG 与对象身份 | 默认无额外运行时成本，但静态分析耗时需测量；不承诺完整别名覆盖 |
| 有界跨函数摘要（长期后续） | 改善 wrapper/error/回调风险链及误报，复杂度中等 | 按需分析，有预算和版本失效；预算耗尽无证据则不报，不拒绝编译 |
| 可选 `go test -race` / `go build -race` | 实际执行时检测所覆盖路径的内存冲突 | build 只生成插桩产物，须运行才有报告；有时间/内存开销，不能检测所有死锁或未执行路径 |
| 可选业务测试/调试包装 | 验证锁协议与关闭状态 | 增加运行时检查或状态可能改变性能/行为，需显式选择，不默认插入 |
| 严格借用/所有权模式 | **未批准备选，不是默认路线** | 生命周期、精细别名与跨包证明复杂；不能以此为普通 Go API 的前置条件 |

默认诊断方向追求高信噪比，不为了“全安全”增加普遍包络限制。warning 消失可能只是分析没有证据。Go 的 race 报告、静态 warning 和 enum 的运行时边界错误分别记录，不互相代替。

## 5. 证据、自审与历史状态

[Go 夹具](../../../tests/design/lock/boundary_test.go)继续验证方法值/error/panic 可保留原指针、浅复制别名、Go Read 可写及数组快照独立性。它们现在是“普通 Go 行为与 warning 动机”的证据，不再标成未来 goxide 必须拒绝的程序。新增局部指针返回和只读并发共享正例，防止把 GC 有效对象与锁协议期限混淆。测试不故意制造数据竞争或死锁，不通过检测器没有报告来证明程序安全。

本轮自审：删除“无摘要→unsafe”“未知→拒绝”“任何借用返回→错误”；检查 error/panic 不清除来源但也不是天然错误；区分读类型直接写 error 与其他别名写 warning；区分静态可能冲突与运行时 race；保留真实 ABI/trait/match 错误；U15 明示 D11 接合待协调。前两轮严格默认与三项推荐中依赖严格准入的部分已被用户否决，不能因历史验证通过复活。当前仍无 goxide 前端诊断测试，只有 Go 机制测试和文档检查。
