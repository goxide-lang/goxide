03 / OPTION + RESULT

显式处理缺失与失败

Option[T] 与 Result[T,E] 区分不同结果。有限上下文中的 ? 传播失败，Go 的 error cause 链可以保留。go_result! / go_result_keep! 显式适配 Go 返回值，按静态签名推导 T/E，并以原错误类型判断 nil。

版本、包支持与复现
直接支持以下包及构建时随附的依赖闭包。其他包会给出诊断；完整闭包记录在 构建清单。不提供目录编译、本地模块、文件系统和网络导入。

边界也是语言说明的一部分
这不是完整 Rust，也不是全部 MVP。
语法是有限子集完整 trait、用户过程宏、.hgo 用户泛型定义与 LSP 尚未交付。部分 match / ? 表达式组合仍会拒绝。跨模块 Result 的特定循环已消除逐项分配；最终结果仍可分配，不承诺零分配。RFC 展示不等于实现支持。
协议有资格要求派生不隐式授予所有类型协议。递归 Default、循环容器 equality、手写 Clone / Debug / serde 登记仍有缺口。
没有完整借用保证路径只读不等于全局不可变，写引用不承诺独占。这里不宣称完整 Rust 借用安全；复杂别名分析是独立工作。
浏览器范围小于 CLI这里只转译单文件与随附包。跨模块恢复、构建视图、测试文件与交叉平台有各自边界，应按仓库验收矩阵验证。
