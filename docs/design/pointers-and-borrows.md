# 指针拆分、引用权限与借用边界

状态：本文汇总已讨论的指针场景，区分**已确认方向**、**暂定规则**与**未定问题**。没有完整借用规范或检查器实现；示例用于表达语义，不冻结最终语法。

三态定义与跨专题决策以[决策登记](decisions.md)为准。

## 1. 已确认的方向

- hgo 是转译器、转译前 linter 与普通 Go 支持库，不以引入完整 move 系统为前提。
- 拆分 Go `*T` 承担的可选性、写权限、避免复制和共享对象身份；Option 表达“可能不存在”。
- 使用 `mut& T` 表达写引用，由编译期检查处理独占访问；不以 `mut T` 隐藏引用语义。
- `Arc[T]` 作为共享句柄，后端使用普通 Go `*T`。复制句柄仍指向同一对象，不另加原子引用计数运行时。
- 每种源级能力都要描述 Go 降低和双向互操作。原生调用通过 Ptr / AsPtr、unsafe 和普通 declare 表达边界，见[原生 API](foreign-api.md)。
- 锁句柄采用指针表示，回调访问受保护数据；带独立泛型返回类型的 Do 使用 Go 1.27，见[锁专题](synchronization.md)。

用户提出以 `-race` 补充检查。应保留这一验证方向，但 `-race` 是编译时插桩、运行时发现实际执行路径上的竞争，并非编译期独占证明。开发 / 测试配置是否默认启用、支持平台和发布配置仍未定；语言权限规则不能依赖某次运行有没有报告竞争。[Go race detector](https://go.dev/doc/articles/race_detector#How_To_Use)

## 2. 暂定的源级模型

下表是供实现前确认的最小模型。尤其 Arc 非空、读借用复制和写借用重借用的具体规则，不能仅因已有 Go 表示就视为已经冻结。

| 形式 | 暂定源级语义 | Go 承载与限制 |
| --- | --- | --- |
| `T` | 普通值，默认延续 Go 赋值复制 | Go T；不可复制资源及含借用值的例外规则需补齐 |
| `&T` | 非空、受作用域限制的读借用 | Go `*T`；后端指针本身不表达只读 |
| `mut& T` | 非空、借用期间受独占访问检查的写借用 | Go `*T`；写权限不能自由复制 |
| `Arc[T]` | 暂定非空、可复制的 GC 共享句柄 | Go `*T`；不自动使对象线程安全或可独占访问 |
| `Option[Arc[T]]` | 可缺失的共享句柄 | 首版按 Option 表示；单指针优化仍是独立候选 |
| `Ptr[T]` | 可空、有类型的裸指针，不提供借用保证 | `type Ptr[T any] *T`，单层指针转换已做 Go 实验 |

`Arc` 非空的建议用于把“是否存在”交给 Option；Go 公开入口仍能收到 nil，必须按实际选定的目标类型检查。Go GC 保持可达对象存活，不证明只读、独占、锁保护或业务资源仍打开。

早期讨论中的共享 `Ref[T]` 与 `mut self` 已被后续的 Arc / `mut&` 方向替代，不作为另外两组已确认类型保留。早期 trait 示例中的 `*T` 只说明 Go 接收者身份，不能重新成为绕过权限体系的通用 safe 指针。

## 3. 创建、复制与重借用的草案

建议首版先检查局部、可追踪来源的借用，不要求立刻实现生命周期参数或跨整个依赖图的所有权证明：

```hgo
r := mut& value
update(r)          // 暂定为本次调用的短期重借用
// copied := r     // 不允许复制一份可独立使用的写权限
```

重借用期间，原写借用暂停相应访问；调用完成后能否恢复，取决于被调用者确实没有保留或派生逃逸别名。普通 Go 函数类型不能表达这个事实，外部调用需要可信 declare 或实际包装。首版建议限制写借用的普通存储、返回、逃逸闭包及 goroutine 捕获；允许哪些显式借用返回或重新借用形式仍未定。

多个读借用可以在兼容的有效范围内共存，这是暂定规则。读借用的“只读”范围必须覆盖受保护存储上实际可达的写操作，不能只禁止 `r.field = value`，却允许经 slice、map、方法或回调修改同一存储。

`Arc[T]` 可复制，所以从一个 Arc 变量不能直接推断整个对象唯一。建议在已共享或交给未知 Go 代码后不自动形成 `mut& T`；修改通过遵守共同协议的锁、原子操作或经过审核的线程安全 API 进行。未来若可证明某个局部范围内不存在冲突访问，可以细化此规则；证明方法与可接受程序范围尚未确定。

这些限制属于拟议 linter 规则，不能靠让 Go 编译器拒绝指针复制实现。检查应在生成 Go 前完成，并在 IR 中保留权限、来源和有效范围；含借用的 trait 视图、闭包、enum 或容器仍受同一来源约束。

## 4. 解引用先表示存储位置

用户提出的解引用场景需要区分“位置”与“读取一个值”。建议将 `*r` 首先解析为可访问的存储位置，再根据使用上下文检查权限和复制行为：

| 源级操作示意 | 暂定含义 |
| --- | --- |
| `r := &value` | 对合法可寻址位置建立读借用，不默认创建长寿命 Arc |
| `r := mut& value` | 对合法可寻址位置申请受检查的写借用 |
| `x := *r` | 从位置读取 T；值上下文发生复制，要求该复制被允许 |
| `*r = replacement` | 改写被引用的位置，要求对应写权限 |
| `r = other` | 改变本地引用绑定；不能据此消除旧借用的来源或义务 |
| `r.field` 或引用接收者调用 | 可考虑自动解引用，但不先复制整个 T，也不增加权限 |

取址、赋值与自动解引用的完整语法、是否允许重绑定借用变量、对重叠字段的粒度仍待设计。示例不授予裸 Ptr 同样的 safe 操作权限。

可寻址检查不得静默给 map 元素或临时表达式制作一份副本，再声称借用了原位置。slice 元素引用指向当时的底层存储；append 后的新 slice 可能更换数组，旧引用不会自动跟随相同索引。返回原对象的引用和返回其副本的引用必须在语义上区分。[Go 地址操作](https://go.dev/ref/spec#Address_operators)、[Go append](https://go.dev/ref/spec#Appending_and_copying_slices)

## 5. 避免复制、分配与 Box

避免复制大对象可以用受限借用或共享句柄表达，但“因为大所以不复制”与“语义上禁止复制”不同。对于锁等具有复制限制的类型，建议增加明确的不可复制约束或仅通过句柄流转的规则；约束如何声明、如何传递给包含它的 struct 和泛型参数，仍是未定设计，不能假定已存在 `noncopy` 关键字。

**Box 是否进入首版尚未确定。** 如果未来的 Box 仍可自由复制且没有独立的唯一性规则，它最多表达某种间接存储或共享句柄，不会仅凭名字获得唯一所有权。是否有区别于 Arc 的必要存储、资源或使用限制，应先给出需求再决定。

构造可引用对象的函数名称及签名也未定，例如可以由基础包提供返回 Arc 的构造。它表达创建一个可被引用的对象，不承诺物理上始终堆分配；具体栈 / 堆选择继续由 Go 编译器决定。分配存储与文件 Close、锁 Unlock 等资源生命周期也不是同一件事。[Go 栈与堆分配说明](https://go.dev/doc/faq#stack_or_heap)

## 6. 嵌套别名、输出槽位与其他 nil

外层 struct 的复制或独占借用不自动覆盖其所有可达对象。slice、map、Arc、接口和闭包可能保留原存储；把它们装进锁、trait 视图或 enum 也不会消除已有别名。首次边界检查只能证明当次取得的值，不能保证外部共享字段以后仍满足非空或合法 enum 不变量。

用户提到的其他指针职责，暂按以下清单保留，尚未形成完整映射：

| 场景 | 必须进一步区分的内容 |
| --- | --- |
| Go `**T` 与输出参数 | 修改对象，还是修改保存对象引用的槽位；不能机械解释为两层 Option |
| 含指针的 struct / slice / 函数签名 | 原生 Go 布局保持真实身份；`[]*T` 不能假设与含具名 Ptr 的另一类型直接等价 |
| nil slice / map | 长度为空、可读取行为和可写入行为不同；选择统一或区分 nil / empty 需按 API 决定 |
| nil channel / 关闭 channel | 永久阻塞的接收与关闭后的接收不同；nil channel 在 select 中禁用该分支，关闭后产生零值的路径需处理 |
| nil func / nil interface / typed nil | 不同的调用和动态类型语义，不能只做一层 nil 判断后统一视作 None |
| 图与循环引用 | Arc / Option 表达身份和边；递归验证及修改的别名策略另定 |
| cgo、unsafe.Pointer、uintptr | 另有原生 ABI、可达性和存活约束，普通 Ptr 不直接授权任意数值地址变成 safe 引用 |

例如把“可修改的可选句柄槽位”写成某种高层借用，仍需要验证其 Go 表示是否与 `**T` 兼容。Option 的通用 interface 表示不等于 `*T`，不能用表面相似的两层指针拼写省掉实际桥接。单层 Ptr 的 Go 实验不证明递归布局全部零成本相容。

Go 的 nil 与容器行为由各自类型定义；hgo 应逐类建立视图，不把所有 nil 统一变成一个没有上下文的缺失值。[Go 零值](https://go.dev/ref/spec#The_zero_value)、[Go 类型](https://go.dev/ref/spec#Types)

## 7. 与锁、原生 Go 和 unsafe 的连接

`Lock[T].Do` / `RWLock[T].Write` 的回调获得受限制写访问，Read 获得读访问；复制锁句柄仍操作同一把锁。借用不能随结果、闭包、容器或 trait 视图离开回调。锁构造对 T 的浅复制仍可能保留外部别名，所以“放入锁”不是对整个对象图独占性的自动证明。

原生 `func A(*T)` 的默认 raw 视图使用 Ptr；普通 declare 可以采用已审核的读借用、写借用或共享句柄契约。AsPtr 在 unsafe 表达式中导出后端指针，不代表 unsafe 表达式结束后外部别名自动消失。反向从 Ptr 建立 safe 引用至少需要相应的非空、权限、期限和同步依据，判空本身不充分。

独占访问与逃逸检查的首版算法、别名来源的精度、保守拒绝范围及泛型 / 接口 / 递归对象的处理均未定。本篇只保存必须处理的问题与暂定边界，不把这些要求写成已经实现的完整借用证明。

## 8. 实现前验收清单

1. 源级类型与 Go 表示分别保存；相同 `*T` 布局不能使 Ptr、Arc、读借用、写借用互换。
2. 值读取、位置写入、引用重绑定及自动解引用分别检查，禁止隐藏的临时复制与权限提升。
3. 已选定的复制、重借用和逃逸规则有通过及拒绝样例；trait / enum / 容器装箱不能绕过它们。
4. 非空初始化、Go 公开输入、输出参数及嵌套容器分别验证，不将单层指针实验扩大成完整布局证明。
5. 锁回调与外部声明维持同一来源约束；`-race` 验证结果与静态检查结果分开报告。
6. Box、不可复制约束、借用返回和别名算法在定稿前保留未定状态；未实现形式给出明确诊断。
