# RFC 0005：Arc、读写借用与解引用

## 状态与范围

- 已确认：`Arc[T]` 使用 Go GC 共享对象；`mut& T` 表达受检查的写引用；不引入全局 move 系统。
- 已确认的访问方向：`&T` 为只读路径，`mut& T` 为可写路径；普通引用允许复制、保存和返回，不承诺独占。
- 暂定：Arc / 引用的非空与构造协议、接收权限及完整投影类型表示。下列未冻结语法仍是候选。
- 未定：完整投影类型检查、返回签名覆盖、接收权限、明确不可复制类型及 Box。Box 的名称不构成唯一所有权规范。
- 本文规定源级权限与 Go 存储的对应关系，不把成功生成 `*T` 当成已完成借用检查。

D19/D20 边界：读写权限和已确认类型不变量照常检查；别名、留存、独占与重入风险分析独立长期推进，不属 MVP。未来仅有具体风险证据才 warning；未知不默认拒绝或告警。

设计背景：[引用专题](../design/pointers-and-borrows.md)。匹配中的借用见 [RFC 0009](0009-match.md)。

## 源级规则

| 源级形式 | 候选含义 | Go 表示 |
| --- | --- | --- |
| `T` | 值；读取允许复制时遵循该类型的复制规则 | `T` |
| `&T` | 经所选路径只读，不增加写权限，也不冻结其他别名 | `*T` |
| `mut& T` | 可复制的写访问，不承诺独占 | `*T` |
| `Arc[T]` | 可复制的共享句柄，复制保持对象身份 | `*T` |
| `Option[Arc[T]]` | 表达可缺失的共享句柄 | 由 enum ABI 决定 |

`*r` 首先表示一个存储位置：值上下文读取它，赋值上下文写入它。
自动解引用即使被支持，也不得先复制整个对象，或使读借用获得写权限。
建立引用和投影时要保存读写资格；相同的 Go 指针类型不能消除这些源级区别。
传参不自动暂停原写权限，也不要求先证明被调方未留存。若未来 API 声明临时访问契约，其违规风险按 D19/D20 另行研究，不恢复默认逃逸拒绝。
Arc 的共享性不自动授予独占访问；锁、原子或其他受审核协议另行提供访问途径。

## 转译示例

以下都是函数或函数体片段；`i32` 降低为 `int32`，`Item` 为已定义的普通对象类型。

**B01：解引用的读取与写入。** 两个函数分别检查权限；不增加运行时权限对象。

```hgo
func read(r &i32) i32 {
    return *r
}
func update(r mut& i32) {
    *r = 42
}
```

```go
func read(r *int32) int32 {
    return *r
}
func update(r *int32) {
    *r = 42
}
```

**B02：局部写引用与直接传参。** `update` 的写访问资格已知；接受调用不依赖不留存证明。

```hgo
var value i32
r := mut& value
update(r)
*r += 1
```

```go
var value int32
r := &value
update(r)
*r += 1
```

约束：`r` 始终指向 `value`。不得复制 `value` 后把副本的地址传给 `update`。
取址是否使 `value` 逃逸到堆上由 Go 编译器决定，不承诺零堆分配。

**B03：复制共享句柄。** 片段的输入 `a` 分别具有 `Arc[Item]` / `*Item` 类型。

```hgo
b := a
```

```go
b := a
```

约束：`a`、`b` 指向同一对象；无深复制，无额外原子引用计数。
复制不会凭空新增 Arc 的写访问 API；可取得的访问须符合其已声明协议。预先存在的可写别名不会仅因可能冲突而被拒绝，Arc 的具体访问方法仍待定义。

**B04：读借用写入应被拒绝。** Go 可以表达该操作，因此错误必须由 hgo 检查。

```hgo
func wrong(r &i32) {
    *r = 42 // 拒绝：经读借用写入
}
```

```go
// 禁止生成：这段 Go 可编译，但违反源级读权限。
func wrong(r *int32) { *r = 42 }
```

## 拒绝与边界

- `a := r; b := r` 可以复制同一 `mut& T`，保持对象身份与写资格；这不提供独占或无竞争保证。
- 不能偷偷复制 map 元素或临时值，再把副本的地址当成原位置的借用。
- 引用装入 enum、trait wrapper、容器或闭包后仍须保留读写资格；尚不能表达资格的类型边界可以明确报未支持，不能以此泛化为逃逸禁令。
- 读借用的禁止写入包括通过字段、方法及其派生别名修改受保护存储；检查精度仍未定。
- 共享字段的浅复制可能保留 slice / map / Arc 别名；借用外层 struct 不自动证明整个对象图独占。
- 普通引用返回和跨 goroutine 捕获不因留存或并发本身而拒绝；具体未支持的签名或资格传递形式须准确诊断。并发写冲突风险与类型错误分开。

这些边界约束类型资格与真实存储身份；不要求全程序别名分析或不逃逸证明作为准入条件。

## 双向互操作

hgo 调 Go 时，涉及引用/原生指针的实际类型桥接按 [RFC 0006](0006-foreign-api.md) 处理；普通未知 Go 调用不因缺少声明而拒绝或自动 unsafe。
`declare` 可描述读写契约，但验签只能证明 ABI 兼容；声明作者承担其明确承诺的不留存、无冲突重入等行为前提；没有此类摘要不构成默认拒绝理由。
Go 调生成函数时只看到 `*T`，普通 Go 调用方不获得 hgo 的静态只读检查；hgo 本身也不承诺独占或期限证明。
公开边界的非空检查方案见 [RFC 0015](0015-public-api.md)，判空不能证明独占。
模块中的 `.d.hgo` 保存源级权限；hgo 消费这些信息，Go 工具链只编译 `.go`。
本方案不要求给第三方原生 Go 程序追加一套 hgo 静态检查。

## 验收与未定项

1. B01–B03 验证读取结果、原存储更新和共享身份；B04 在生成 Go 前拒绝。
2. 增加写引用复制、普通返回及捕获的正例；只读升级和权限擦除为负例。具体别名冲突的未来 warning 单独验收，不计入 MVP。
3. 检查 IR 到 Go 的每次值读取和取址：复制不能替代原位置借用，布局相同不能提升权限。
4. Arc / 引用非空、构造与更宽返回签名、投影粒度和明确不可复制类型尚未定稿；这些待定项不撤销普通引用可复制、保存和返回的方向。
5. Box 仍待设计；不生成没有已定义语义的 Box ABI。
6. `-race` 只补充实际运行路径的竞争证据，不能替代转译前权限诊断。

当前验收表是完整特性的设计要求；仓库已有有限引用与投影前端，范围见实现记录。Go 夹具不能代替未实现的源级检查或长期 warning 分析。

### 6.15 同模块公开引用权限元数据首片（2026-10-02）

本节落地已批准的路径只读/可写规则，没有增加独占、全局不可变、逃逸限制或长期别名分析。D11 显式原生桥方向不变：原生 `*T` API 保留原行为，检查过的引用不得借 Go 指针表示静默擦除权限。

同一次目录构建按 import 依赖顺序完成 provider 全包权限检查及最终 Go 类型检查，再发布内部 v1 元数据。当前支持公开普通函数的内建标量 `&T` / `mut& T` 参数和单个非具名引用返回值；同包多文件、导入别名、跨包转发返回、显式写转读收窄都保留权限。普通 slot 的私有或传递依赖类型通过 provider 生成的透明类型别名命名，保留 Go 类型身份，不要求消费端额外猜测 import，也不改变同名普通方法的调用。

元数据键为真实 module/import path 与包作用域函数对象；参数/返回位置记录完整 Go 类型身份和引用权限。内部 `Version=1`、path、签名和 JSON 摘要由 `HgoReferenceMetadata` 常量标记核对，普通 slot 别名另核对 Go nominal identity。目录产物中的 `.hgo.refs.json` 用于审计；当前只信任本次构建内存注册表，不从 sidecar 恢复外部包，不承诺稳定公共 ABI。透明别名、marker 与文件格式都属于当前内部生成协议。

消费端包括没有新引用语法的 `.go` 文件。检查期间将解析到的导入函数调用呈现为本地名义权限签名；完整权限检查后删除分析函数并还原原调用。函数值/回调、dot import 及其他未支持位置明确诊断，不能退回普通指针规则。元数据缺失、版本/路径/摘要/签名不一致必须拒绝；无 marker 的普通原生包不是“缺失 hgo 元数据”。marker 不是防篡改签名，也不为任意手改 Go 产物建立可信历史。

单文件产物的公开引用也生成 marker（内部路径 `hgo/generated`）；单文件消费者无论有无新引用语法都会检查导入 marker。跨构建没有可恢复权限注册表时，在导入位置明确报缺元数据；单文件 marker 只防止自动降级，不表示已实现外部依赖恢复。原始未检查 Go 调用者仍能写入普通 Go 指针，不存在运行时权限包装。

[真实模块验收](../../tests/acceptance/reference_metadata_test.go)覆盖别名与空白重复导入、同名包路径、同名普通方法、类型私有性、多文件、返回转发、defer/goroutine、既有可写别名可见性、Go 消费者的写入/接口/指针/闭包擦除拒绝、单文件两方向缺失诊断、重复构建字节确定性及生成模块单独 race/vet。[元数据验证单测](../../internal/refs/metadata_test.go)覆盖版本、路径、摘要、完整签名和权限值。新导入/函数值错误有原始 source span；后端引用重建错误仍明确 `generated/unmapped`，未声称所有位置精确。

剩余工程缺口：复合/具名元素的公开引用、方法/泛型/引用容器/回调、named/multiple result、dot import、跨构建/外部源码依赖恢复，以及更完整的来源映射。这些不是新语言禁令或自动批准延期；完整外部 ABI 与 native bridge 的待决部分另行处理。

### 6.16 同模块复合元素权限元数据（2026-10-02）

在 §6.15 已定规则上扩展具体 struct、slice/map/array、非泛型具名元素和递归指针组合，公开签名仍限普通函数的参数和单个非具名返回。内部格式升至 `Version=2`；引用 slot 新增元素透明 alias，消费端验证 alias 与实际 Go 指针元素身份一致，解决私有类型和再导出类型的命名问题。普通 slot 保持既有完整签名校验；不读取外部 sidecar。

检查 IR 从按元素源码拼写区分的名义类型改为共享泛型名义读/写源，实例参数是实际 Go 类型。相同类型的别名/import 拼写得到同一身份，不同 defined type 或包路径不会因布局/短名相同而合并。具体辅助 alias 带文件 namespace，防跨文件同一 import 短名碰撞；识别内部引用还要求当前检查包对象身份。类型约束使用 `interface{}`，不受用户 `any` 定义影响。生成 Go 前删除实际登记的分析声明并擦除引用，不靠名称前缀删除用户声明。

返回值与转发保留既有投影规则：标量及数组/struct 副本的独立值部分可写，其中 slice/map/pointer 等共享投影不能借复制、接口或方法路径擦除权限；这里没有引入完整方法效果协议。其他可写 alias 与普通 native 指针仍可更新原存储；只读路径可观察更新。对容器的引用已支持，不等于容器中携带新引用已支持。

[模块验收](../../tests/acceptance/composite_metadata_test.go)走真实 CLI→生成 Go，覆盖多文件/再导出/私有类型、同名不同包、显式收窄、容器和读写正反例、两次生成确定性；生成模块独立 race/vet。权限检查包括经过 hgo 的 `.go` 消费文件，但原生 `go build` 不执行它。透明 alias 和 marker 不是原生 Go 的只读机制，也不是稳定外部 ABI。

尚未支持 interface/channel/function/用户泛型元素、引用方法/回调/引用容器、named/multiple result、dot import、外部恢复。既有投影保守限制与来源映射缺口继续列工程待办，不默认为批准延期；D11 待决部分和长期别名分析保持原分类。

### 6.17 普通局部权限事实与控制流（2026-10-02）

D19/D20 要求不因无法证明别名安全而默认拒绝普通 Go 用法；D08/D21 仍要求只读路径写入和权限擦除属于基础类型错误。本节不引入风险分析或新桥接，修正已有实现把某槽位曾有只读资格永久套到后续独立存储的误拒。

以下五个最小真实 hgo 例子均使用 `func f(r &S,b bool)`、`type S struct{Items []int}`，`touch([]int)` 是普通写入函数。修复前 CLI 均拒绝；前四类现已接通，第五类仍明确保留为工程缺口：

| 最小函数体片段 | 类型事实与本阶段结果 |
| --- | --- |
| `x:=r.Items;for i:=0;i<2;i++{x=[]int{1};x[0]++}` | 每次写前强重绑定到独立存储，允许；零轮出口不能假设已重绑定 |
| `for i:=0;i<2;i++{x:=r.Items;x=append([]int(nil),x...);touch(x)}` | 复制 int 元素后的新 slice 可传普通 Go 参数，不要求 callable 效果摘要，允许 |
| `x:=r.Items;if b{return}else{x=[]int{1}};x[0]++` | 返回分支不参与后续汇合，继续执行路径已经独立，允许 |
| `x:=r.Items;p:=&x[0];x=[]int{1};x[0]++;_=*p` | 取元素地址不等于取局部 slice header 地址，允许；通过旧 p 写仍拒绝 |
| `v:=*r;v.Items=[]int{1};v.Items[0]++` | 应按替换后的字段处理；当前字段级强更新尚未实现，仍误拒，不能写成已批准语言限制 |

实现使用有限函数内资格环境：不可达出口区别于可达且无只读资格的空环境；if 合并仅继续执行分支。for/range 入口合并回边直到固定点，再保留该轮完整事实；continue 经过 post，break 和标号退出进入实际目标，可能零轮的循环保留入口出口。range 源资格在源表达式求值时保存，不随循环体内重绑定源变量变化；每轮迭代变量和无初始化 var 重新建立资格。迭代求解不改变生成 Go 控制流，没有新增运行时状态。

取址仅将真实被取址的局部槽位或值型 struct/array 根保守保留。`&slice[i]`、`&*p` 不暴露 slice header 或局部指针槽位；派生指针单独保留旧存储资格。`&x`、值型字段/array 元素地址和捕获仍有保守限制，不推断跨函数调用效果。switch/select/goto 与包含未建模 switch/select 的循环继续保守处理；这不是获批语言禁令，也不意味着复杂堆别名分析成为 T0 前提。

[真实跨包验收](../../tests/acceptance/refs_control_flow_test.go)包含已检查 provider 返回引用、普通调用、分支/循环/标签、独立值复制、元素取址与每轮零值声明；生成模块另跑 race/vet。负例保留 readonly 回边、零轮路径、continue/post、break、旧 alias、range 源冻结、接口擦除和捕获/取址槽位。可写 alias 不因存在只读路径而禁用；没有把真正类型错误降成 warning。

### 6.18 局部值字段替换（2026-10-02）

接通 §6.17 第五个误拒例：`v:=*r;v.Items=[]int{1};v.Items[0]++`。只更新独立局部 struct 值中的已知字段路径，包含嵌套字段和值型嵌入 promotion；每一级使用真实 Go selection，不能穿过显式/隐式指针或容器索引。字段可以接收带资格的值并保留资格，再被新值替换；局部副本不是因为曾接收只读来源而永久只读。

| 最小例（r 为相应 struct 的只读引用） | 当前结果与原因 |
| --- | --- |
| `v:=*r;v.Left.Items=[]int{1};v.Left.Items[0]++` | 允许；仅替换局部值的该 slice header，后续写访问新 slice |
| `v:=*r;old:=v;v.Items=[]int{1};old.Items[0]++` | 拒绝；旧值副本仍保留共享旧 slice 的资格 |
| `v:=*r;v.Items=[]int{1};v.Counts["x"]++` | 拒绝；替换 slice 字段不改变 map 兄弟字段的资格 |
| `v:=*r;v.P=&fresh;*v.P++` | 非捕获/未取址的局部根允许；替换指针字段与通过原指针写入是不同存储路径 |
| `v:=*r;v.P.Items=[]int{1}` | P 为旧共享指针时拒绝；不能把 pointee 字段当独立局部值路径 |

资格树持久化更新，不原地修改 map/子树，旧副本和已记录语句点仍引用原资格。保守 summary 弱合并字段赋值；支持的局部控制流对非捕获/非取址根强更新。多赋值先记录全部 RHS 资格，再按 Go 写入阶段从左到右更新根或字段，`v.F,v=...` 与 `v,v.F=...` 不交换顺序。if/循环汇合保留未替换分支、零轮和回边；range 字段目标也保留源元素资格。返回/接口/普通调用不能擦除未清除的其他字段资格。

独立审查发现 Go 指针接收者的隐式取址漏记：方法保存 `&v` 后，`v` 再取得只读共享字段，会使另一条未带资格的指针路径获得写入能力。本片通过真实 method selection 识别值 receiver 的隐式取址（含方法值和值型 promotion），复用实际取址槽位的保守处理；已有 pointer receiver 不因此将局部指针 header 判为已取址。这里不分析方法体、留存、重入或独占，普通无只读资格的 Go 方法保持可调用。

字段路径的存储更新只沿有限 AST 选择链重建资格节点及祖先字段 map，复用现有函数内回边收敛；没有新增生成 Go 运行时开销。跨 heap alias 的字段写入、数组/容器元素逐索引强更新、捕获/真实取址根、未建模控制流仍有精度缺口。扩展这些路径需分别处理别名可见的槽位、索引重叠或局部控制流；不能用单个 root 字段 map 假装解决，也不因此启动长期全程序 alias 分析。本片不宣称全部字段场景完成。

[真实 CLI 模块验收](../../tests/acceptance/refs_field_flow_test.go)覆盖 10 个业务函数、2 项生成模块 race 测试与单独 vet，以及 24 个拒绝反例；slice/map/pointer 替换、嵌套和值嵌入、旧副本/兄弟字段、RHS快照/写序、循环/range、接口和隐式取址分别验证。原生 Go build 仍不执行 hgo 权限检查，D11 自动桥接与 D20 长期分析未改变。

### 6.19 暴露局部槽位与当前值（2026-10-02）

捕获/取址不再永久阻止整个局部槽位直接替换后的精化。`x:=*r;_=func(){_=x};x=[]int{1};x[0]=2` 和 `_=&x` 对照均允许：最后写入独立新值。普通 x 使用点保存当前资格；`&x`、值字段/array元素地址、隐式取址方法以及闭包捕获入口仍采用该槽位的 lifetime summary，不能让旧地址或晚调用闭包绕过后续 readonly 赋值。旧 slice/struct 副本保留其原资格。

没有 callee effects 或指针 alias 图。可能调用、channel 收发、函数 iterator/通道 range 的隐式调用/接收，以及能替换复合值的间接写入，在读取标注前恢复暴露槽位的 summary；间接多赋值写阶段结束也恢复。直接整槽替换随后可重新精化。普通标量元素写不改变槽位资格；内建非回调操作和类型转换不当成未知调用。无数据竞争的 channel 同步重绑定负例仍拒绝。

这修复已复现的整槽重绑定误拒，不宣称所有捕获/取址操作完成。暴露对象部分字段强更新、未知调用后的精度与未建模控制流仍留工程账，不将这些限制宣布为新的安全规则或获批延期。[真实跨包 CLI 测试](../../tests/acceptance/refs_exposed_flow_test.go)包含独立生成模块 race/vet、旧地址/闭包/同表达式调用/间接多写/同步反例；不增加运行时包装或正常传播 panic。

### 6.20 具体标量原生写指针参数（2026-10-02）

按 D31，具体标量 `mut& T` 可直接传给真实元素同型、Go 可赋值的普通 `*T` 参数。权限检查后直接生成 Go 指针调用，支持原生函数值/定义函数类型、变参及 defer/go；不引入引用 callback 适配。callee 可保留/返回指针，readonly 仍不可升级，&T 仅限制当前路径。规则与历史 D11 更正见[桥接研究更新](research/0002-native-pointer-bridge.md)；[实际多包验收](../../tests/acceptance/native_write_bridge_test.go)单独 race/vet。复合元素/定义指针类型及其他擦除位置未由本片完成，也不宣称其为获批永久限制。
