# Generated Go readability: bounded lowering changes

Baseline: ae61ec628b55e0fc66ce96d47261c0a6809c0280. This work does not
change the shared-stdlib design, enum case identity, or public HgoInst names.

## Before / after contract

1. A concrete builtin validator currently calls its family validator, then emits
   a payload type switch even when every arm is only `_ = payload`. Generate that
   second switch only when at least one payload needs validation. Always retain
   the family validation call; nil Option is None, whereas nil Result is invalid.
2. Separate a builtin's private validator name from its exported HgoInst SHA-256
   identity. Use a readable family prefix plus a deterministic short digest for
   the private name, with explicit collision rejection, never silent merging.
   Reserved generated identifiers cannot be captured by source bindings. Public
   metadata continues to store the original full-digest exported name.
3. For fully qualified, unguarded variant arms only, lower a match from
   `if !matched { if payload, ok := saved.(Case); ok { matched = true; body } }`
   to `if payload, ok := saved.(Case); ok { body } else if ...`.
   Save the target once and validate before dispatch. Keep guarded and inferred
   matches on the existing path. Never introduce a switch or closure around arm
   bodies: unlabelled break/continue and direct recover keep their user targets.

Coordination: enums/builtins.go and enums/lower.go are shared with the std work.
The name interface must expose private Validator separately from ExportValidator;
frontend export collection, imported-family fallback and package deduplication
must consume the latter rather than reverse-engineering a private spelling.
No natural-import rewrite, general temp renaming, ABI shortening, or global
formatting pass is included.

Run full local race, vet and scripts/check_design.py; test frontend source maps,

## Implementation and measured output

The private spelling is now `__hgo_enum_checkResult_54ff08137ead5d4c`, while
`ExportValidator` remains
`HgoInst54ff08137ead5d4ca33b5ab78a762fed110119a4e0a0ad7c089db72bd5ca2ae2`.
The 16-hex suffix is not a collision-free identity: lowering and adapter emission
reject conflicting full identities, and package deduplication checks identities
and complete declarations before removing duplicates. Tests inject collisions.
No metadata schema or exported constructor/case/validator identity changed.
Source fingerprints must, and do, change with the new generated bytes.

| Website example | Baseline lines | New lines |
| --- | ---: | ---: |
| macro | 12 | 12 |
| enum | 97 | 88 |
| result | 237 | 200 |
| go_result | 275 | 212 |
| derive | 115 | 115 |

The go_result example changes from 10,387 to 7,683 bytes. Unchanged parts include
macro IIFEs, package aliases that prevent capture, generic family implementations,
guarded/inferred match state, evaluation temporaries and public ABI forwarders.
The improvement is generated-source readability, not evidence of a new runtime
performance advantage.

A local 100ms x 3 optimized benchmark of `next("123")` measured baseline generated
15.60–24.98 ns/op, new generated 20.21–25.31 ns/op; the handwritten equivalent
spanned 15.68–29.69 ns/op across both runs. All had 0 B/op and 0 allocs/op for this
small-integer input. Runs overlapped other validation and are noisy: no speedup
or general allocation claim follows. Original constructors/adapters/validators
already inline; wrapping in source is not necessarily wrapping at runtime.

## Reproducible checks and independent review

- `internal/frontend/readability_test.go` tests evaluation once, break/continue,
  direct recover, nested invalid Result, legal Option None, guarded fallback,
  source-map determinism and an arm literal's exact source line. It also tests
  reserved/source/native-name rejection and cross-file collision injection.
- `internal/enums/builtins_test.go` tests the stable full exported ID, normalized
  private names, same-instance reuse, injected collisions including the adapter
  path, empty scalar validation and retained nested payload validation.
- [control.hgo](../../tests/research/readability/control.hgo) is a CLI-runnable
  control-flow/nested-validation fixture; its output is `1 3`, `kept`, `true`.
- [wasm_parity.mjs](../../tests/research/readability/wasm_parity.mjs), after
  `GO_BIN=/path/to/go python3 website/build.py`, checks the five website outputs
  and eight adapter positive/negative cases against the native CLI. This builds
  local ignored artifacts; it does not publish a website.
- [cross_abi.py](../../tests/research/readability/cross_abi.py), run with
  `HGO_OLD_BIN=/path/to/ae61ec6/hgo GO_BIN=/path/to/go`, builds the current compiler
  and runs all four old/new producer-consumer combinations with race/vet. A
  two-file producer repeats a Result instance; the consumer exercises imported
  `?`, nested match and None-first Option with nil/nonempty slice payloads.
  Metadata is equal across compiler versions while Content fingerprints differ.
