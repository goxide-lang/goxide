# JSON protocol backend prototype

`Encode(serde.WriteValue)` / `Decode([]byte, serde.ReadValue)` run the format-independent serde protocols. `Marshal[T]` / `Unmarshal[T]` accept concrete encode/decode helpers. There is no reflection fallback for application structs and no mandatory core Value tree. The decoder advances `encoding/json.Decoder.Token` with `UseNumber`; byte input and output are buffered, not a streaming I/O API.

Supported: boolean, exact signed/unsigned 64-bit integer, finite float64, UTF-8 strings, null/options, sequences, string-keyed maps, structs, numeric byte arrays, unit enum strings and externally tagged newtype enum objects. Struct name/field-list metadata does not perform field policy itself: the generated visitor owns required/default/skip/unknown-field handling. Native MarshalJSON/UnmarshalJSON methods are not called automatically. Dynamic JSON Value and arbitrary-precision number transport are not yet implemented; Skip can validate and consume numeric tokens outside machine range without converting them. Any selects machine integer or float and therefore can reject valid JSON numeric values that exceed those ranges.

Strict differences from Go's default JSON behavior: duplicate keys (including escaped-equivalent keys and unknown nested objects), invalid UTF-8, and unpaired UTF-16 surrogate escapes are errors; bytes encode as integer arrays; integer targets reject fraction/exponent syntax; float overflow and nonzero-to-zero underflow are errors. Owned strings/bytes are returned. There is one top-level value. Input/output size is bounded at 16 MiB and protocol nesting at 128; option delegation also consumes a nesting level. Field/index errors preserve core error paths. Protocol callbacks must be synchronous and must consume/produce exactly one complete value; writers/readers are not safe for concurrent use. Errors poison the operation even when a callback ignores them. Container length hints are exact when nonnegative; -1 denotes unknown. No transactional guarantee for mutations performed inside user callbacks on a failed Decode.

Run: `GOCACHE=/tmp/goxide-macro-cache GOTOOLCHAIN=local /workspace/goxide-environment/go/bin/go test -race ./serdejson`.

Generated concrete `Option[T]` codecs use the core None/Some protocol: missing struct fields and explicit JSON null decode to None; a non-null value decodes through T's codec to Some. None encodes as null and Some encodes its payload. Even if all runtime values are None, non-skipped fields require T's codec for the derived direction. Option's Default is None and never calls T's Default; `serde(default)` does not construct Some(default T). Invalid present values do not fall back to defaults.

Nested options do not preserve PATCH's missing/null/value distinction: Some(None) and None can both encode as null, as can Some(nil) for nullable pointer payloads. Existing enum payload and projection restrictions still apply; this is concrete builtin support, not general generic or cross-package codec resolution. See the [serde RFC](../docs/rfcs/research/0006-serde-core-and-formats.md#72-内建具体-option-派生) for frontend boundaries.

`serde(skip)` ignores the input's target type and does not invoke its codec. Skip still consumes one syntactically valid value, including duplicate-key, Unicode and budget checks. For example, a skipped Option[int] may receive an object and still default to None, while a malformed or duplicate-key object is rejected. Output omits the skipped field.

Backend Token and numeric-conversion errors retain their actual Go cause beneath the existing serde kind/path. `errors.As` can recover `*json.SyntaxError` (including its original Token offset) and `*strconv.NumError`; `errors.Is` retains underlying sentinels. Offsets are those of the actual backend call, not reconstructed `json.Unmarshal` positions. Checks performed solely by this backend, such as an extra valid top-level value or detected float underflow without a strconv error, do not invent a cause. JSON Value, native JSON adapters and PATCH field adapters remain unimplemented directions; ordinary explicit Go calls and handwritten typed helpers remain available.
