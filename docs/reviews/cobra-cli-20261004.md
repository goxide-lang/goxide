## 实现

- Cobra 命令树、中文 help/示例、四种 shell completion；显式 help stdout/0，错误 stderr/1。
- 独立词法检查执行长 `--name`、单字符短选项、受限短组合、带值选项与 `--` 边界；旧
  `-go`、`-offline` 等明确报迁移建议，先于 pflag 的短选项拆分。
- options 必须在 INPUT 前。`run INPUT -- ARGS` 原样传递程序参数，覆盖单文件、Go
  module 目录、goxide 项目；其它命令没有自由参数透传。
- 六个 scripts 动作子命令；保留 `--action`，冲突拒绝，同名项目路径仍可默认 plan。
  不自动选择 cwd，不隐式授信，help/补全不解析项目、下载依赖、执行进程或读取授权。
- CompileRequest、ImportRequest、ScriptsRequest 与服务不依赖 Cobra/pflag。main 统一
  决定退出码；服务保留原有上下文、输入转发、错误包装和 vendor/trust 逻辑。
- 固定 Cobra v1.10.2 / pflag v1.0.9 / 间接 mousetrap v1.1.0；未引入 Viper 或生成器。
  配置、编译器与依赖解析包没有新增 CLI 框架依赖。

## 集成中发现并修复的 Go pruning 回归

触发：项目通过本地 replace 引用编译器模块，新增 Cobra 后，原生依赖包含旧 Go 指令
模块的多层传递依赖。原规划器按作者根的 pruned graph 选版，生成阶段却将每个计划项
提升为直接 require，后者扩大 Go 图。缓存齐全时，原始实际错误为
`generated Go build list disagrees with stable plan for github.com/cpuguy83/go-md2man/v2`；
预期是成功构建并可 `--offline --locked` 重复运行。

修复在 [planner.go](../../internal/project/planner.go)：在每次全新 solve 内执行有界
list→提升 selected roots→list 闭包，最多64轮，稳定后才 graph/download/verify/锁定。
不跨 feature/source round 累积旧节点。保留生成模块严格列表/替换校验，不放行未知模块；
vendor 的独立分支和内容摘要不变。这是本次 Cobra 整合必须处理的实际规划缺口，
不是简单缓存问题。

[独立回归](../../cmd/hgo/cli_dependency_graph_test.go) 使用四个 file-proxy Go 模块和
真实 `.hgo` main：先证明原列表缺少末端，再关闭 proxy，验证闭包、native输出42、
locked重复运行和锁文件字节不变。它不依赖 Cobra 本身作为测试输入。临时 Go overlay 使用修复前 planner 时明确失败
（计划外 `example.org/legacyc`）；当前修复通过（1.297s），独立审查者另跑 race 通过（8.410s）。

CLI 新依赖还要求首次离线使用前预热完整固定图，README 改为 `go mod download all`；
仅缓存直接依赖不保证项目模式的完整 module 操作可离线。没有放宽 offline 的网络限制。

## 本地验证

使用真实 Go 1.27.1：`/workspace/goxide-environment/go/bin/go`。这些是本地检查，不是 CI。

- 真实进程合同矩阵：构建 hgo 二进制，通过 OS argv 执行并检查 stdout/stderr/status；
  36 个旧拼法案例、短选项组合/取值、负值、重复 flags、`--`、未知命令、help 与补全。
  假 Go marker、损坏 manifest 与隔离 trust/target 检查 UI 无业务副作用。
- 三种 run 模式逐项保存空字符串、短横参数、再次出现的 `--` 与 shell 语法文本。
  scripts canonical/legacy 授权与撤销使用同一 identity；三个真实同名目录的六次
  调用均为未授权 plan。模拟 schema 另测未来不同 short 的组合与重复拒绝。
- `go test -race ./cmd/hgo -run '^TestVendor' -count=1` 通过（40.026s）：保留冷缓存
  vendor、版本替换、原校验和、features/targets/trust 与诊断 fixture。
- `go vet ./...` 通过；设计检查通过 96 Markdown、1007 本地链接、24 RFC 结构和
  13 条 Go 机制检查。机制检查不冒充 hgo 编译证据。
- 10 个既有网站 `.hgo` 示例：CLI run 与独立生成 Go 的原生输出一致；各生成模块
  `go test -race` / `go vet` 通过。没有重建网站或宣称 WASM/浏览器验证。
- 独立审查未发现剩余 parser/security 阻断；另验 12 个同名目录案例与 8 个最终
  completion/help 探针。最终 UsageError 增量和依赖图复核通过。

完整 `GOMAXPROCS=4 go test -race -count=1 -timeout=20m ./...` 退出0：CLI 560.205s、
acceptance 434.134s，其余包全部通过。最终 vet 与文档检查也通过；逐包和示例结果见
[验证清单](cobra-cli-validation-20261004.json)。原始日志、独立报告和 native JSON 位于
`/workspace/scratch/cobra-cli/`。

检查过程中，中途编辑阶段的全树运行已主动终止，不计成功；同名目录测试最初错误地
共用 target 根，被既有所有权检查正确拒绝，fixture 改为每项目独立 target 后通过。
10 示例首跑及第一次完整 race 的早期检查因缺少基线锁定 std/serde 而失败。预热完整
固定模块图后又明确复现并修复上述 pruning 问题；最终检查使用 `GOPROXY=off`。
仅下载 go.mod/go.sum 已固定的模块图，没有升级其它版本。新回归初稿使用了错误的
manifest 表名，改为 format2 的 `[[go.require]]` 后重跑；不以错误 fixture 的运行作为通过证据。

## 边界

旧单 dash 长选项是有意不兼容变更；当前调用示例、验收测试和网站构建脚本已迁移，
网站资源由父任务随后刷新。未修改编译器 lowering、enum ABI 或 vendor 实现策略；模块规划包含上述闭包修复，
未实现 clap、test 参数透传、动态远程补全、通用进程/文件系统注入或退出码分类重设计。
没有 merge/tag/公开库推送/网站部署。
